# 内网纵深：网关、维护面与构建链

只暴露一个合作方网关时，攻击面通常不在外网路由，而在「网关代为取数 → 回环维护面 → 同网段服务 → 构建/缓存链」这几跳。每一跳先问清楚：校验发生在哪个字符串上，连接发生在哪个字节上。

## 1. 入口与代取

- 先找保留原方法/头/body 的转发器（proxy/fetch/relay/upstream）；静态目录常泄漏它的服务端脚本与路由配置。
- 用 POST 发一块非 JSON 二进制确认原样透传：能透传即等于把任意内网 TCP 端点降级成普通 HTTP 客户端可达。
- 白名单逐项核对四件事：是否解析成 IP 再比对、是否限端口、是否有出站过滤、是否连接前复核；缺一项即解析差异可利用。
- 先找回显"实际连接 host:port"的字段或日志作为唯一观测点；没有就自建对照（白名单主机 403 vs 目标 200）。
- 校验器与连接器的分界字符逐个测（`\ @ : / ? #`），一次只改一个字节，用无害目标做差分。
- 参数含 `@ : /` 时整体 percent 编码（`%5C/%40`），裸写会被查询串或路径规则拆开。
- 分叉成立的证据是"校验通过 + 正文来自目标服务"，不是"返回 200"。

## 2. 维护面与内部服务

- 回环维护端点（`/config`、`/status`、`/metrics`）通常假设只有本机能访问，因此无鉴权；能连上即可读。
- 实例级秘密（seed、一次性 token）换实例必须重取；仓库残留与页面注释里的凭据先验证是否被加载。
- 内部服务先取命令清单（HELP）再试管理命令；被拒绝的回执（`*-only` 之类）本身就是权限边界证据，据此换路而不是换 payload。
- 会话型服务看三件事：首帧是否要求绑定 nonce、来源是否决定权限、写路径是否让读缓存失效。
- 写入后用"同一逻辑对象、不同字符串 key"（zone 不匹配路径、`./` 与 `.//` 等价族）逼重扫再读一次。

## 3. 云元数据与环境注入

- 元数据地址按云厂商/编排判：通用地址不通不等于没有元数据，逐个厂商地址试。
- 先判编码再解：看是否 base64，解出后看魔数 `1f 8b` 再决定解压；顺序颠倒解不出。
- 取到编排层描述（Pod spec、user-data）时直接找 env 段的注入值，它绕过容器内文件权限检查。
- 元数据有前置 token（IMDSv2 类）时，先证明 token 可取，再谈读路径。

## 4. 同二层与构建链

- 先判三件事再考虑二层手法：进程是否有 CAP_NET_RAW、目标是否同二层、是否无隔离策略；缺一即放弃。
- 不必破解内网服务的 bearer token：同二层下重定向应答"已自带 token 的请求"即可。
- 手工构造响应要补齐 TCP 序号/确认号、IP 与 TCP 伪首部校验和、Content-Length、`Connection: close`。
- 恢复/构建类流程会执行归档根目录的钩子脚本：审计 runner、cache、restore 的"归档内脚本自动执行"行为。
- 回传比较摘要前先 strip：目标文件常带末尾换行，按原始字节比会假失败。
- 每步记录"本跳产出的秘密是否随实例变化"，避免把一次性值写进脚本常量。
