# 阻塞诊断与断点恢复

当重复试探没有新增信息，先定位失败发生在哪一层，再决定是否换 payload。旧笔记中的结论只在记录的输入、版本、实例和观测条件下成立。

## 先查观测链

| 表现 | 最小判别测试 | 结论边界与后续 |
|---|---|---|
| 什么输入都没差异 | 正常值、必然错误值、已知有效值三组对照；同时比状态码、头、正文、连接终止和副作用 | 编码错误、路由未命中、缓存、认证未过都可能造成假阴性；先证明探针到达被测分支 |
| 正常功能也 500 | 同会话交替发合法基线与测试请求，保存原始错误 | 数据库连接拒绝等支持“后端不可用”，不能仅由攻击失败断定部署损坏；稳定复现后停盲试，交接重开实例 |
| EOF / 无回显 | 分开记录 recv 空串、timeout、RST、进程退出码与 syscall 结果 | EOF 不等于崩溃，也不证明没覆盖返回地址；可能为正常退出、协议拒绝、seccomp 或输出 fd 被关闭 |
| 请求总耗时等于 timeout | 查协议的消息长度、结束帧、chunk terminator | 收到业务结束帧就返回；keep-alive 不应等 EOF。TCP 分包不是应用消息边界 |
| 只在脚本失败 | 保存实际发送字节，与成功基线逐字节 diff | HTTP 路径归一化、双重编码、Content-Length、Git Bash 路径转换和换行均可能污染输入 |
| 某 CVE/类名似乎可用但无副作用 | 分别证明版本、依赖存在、解析选项、构造与触发路径，以及反序列化前是否有原始字节黑名单 | 关键词绕过、类加载、autoType 错误、HTTP 200 均不足以证明 gadget 可执行；类名不出现在被禁词表内才算过门 |
| 模拟器里指令全乱码、越跑越偏 | 查 key 状态来源：EFLAGS 初值、syscall 返回值与 RCX/R11、输入字节约束 | 这类 divergence 不报错，只会静默解错；先用独立小程序校准陷阱时序 |
| 跨多实例、读源码后仍无法证伪某路线 | 用"矩阵闭合/源码矛盾/合法基线失败"这类路线放弃判据，而不是只等时间上限 | 30 分钟是复盘提示，不是硬性停止；但继续投入前要写出该路线被证伪的具体条件 |
| 本地解出但目标拒绝 | 从用户输入起正向走完整调用链，加入一个错误候选对照 | 单段原像、补丁版接受和模型自洽不足以代替原始全链验收 |
| 换了很多类型仍只见异常 | 本地反汇编自造数据；保持所有必填字段，仅替换一个值 | 协议语法错、对象未初始化或前序字段失败会遮蔽后续分支；异常类型不能直接映射到业务语义 |
| 长任务拖慢整机、重复启动仍无结果 | 检查已有 PID、日志增长、RSS/私有提交量、矩阵维数和处理计数 | 限制内存与工作进程，先保存检查点；没有输出不代表进程已死，不并行复制同一大任务 |
| 同一路径加任何 query/参数都 404 | 对照无参数基线、缺失路径的标准 404 页字节数与响应头 | 可能是应用路由或守卫在 dispatcher 前拒绝，不是漏洞线索；先确认请求到达哪一层 |
| 本地评分与服务端差 1e-3 量级 | 用同版本/同预处理重算，打印中间量与数值精度 | 多为版本、浮点或输入预处理差异，不是逻辑错；先对齐再改策略 |
| 统计图有字但读不出 | 查 `clip` 是否在转 uint8 之前、是否按段统计、是否混入干扰载体 | 回绕成全白或分段重影会掩盖真实图案，先修表示再调参 |

## 四类重点纠偏

**状态与身份**：JWT 签名有效后，改变一个 claim 并观察目标身份/权限。`sub` 可能只是服务端 session 的索引；破解签名不代表可自选管理员。WebSocket 成功建连也不代表有身份；跨域 WS 是否携带 cookie 取决于目标域、SameSite、浏览器与 Origin 检查。bot 有持久 localStorage 不等于带管理员 cookie；无外部回调不能排除只访问同源的 bot。用同源无害标记确认访问、身份及生命周期。

**随机数模型**：先确认生成 API、输出位、每请求消费量、拒绝采样与 worker 模型。HTTP keep-alive 不保证平台代理固定后端 worker。固定 stride 的 GF(2) 方程不相容，只排除当前采样和模型，不能证明用了 `secrets`。在合成已知状态上校验符号 MT/消元，再尝试留出数据预测与双连接交错；设有限 stride/样本预算，不能无界采集 24-bit 随机值来等待“未来值触发隐藏路径”。预测目标必须有可观察的成功分支。

特别核对输出位的代数表达：CPython 常规 MT `random()` 用两个 word 的高 27/26 位拼 53 位；`int(random.random()*2**24)` 恰为第一个 word 的高 24 位，固定消耗两个 word，不能因出现浮点就判为“非 GF(2)”。`choice/randrange` 的拒绝采样、取模映射、混流另行分析。拟合历史样本只是回放，预测必须用未参与求解的留出数据；“recovered_words”这类文件名也不保证存的是内部状态，读其序列化代码确认。

**协议实现**：先用最小合法请求稳定得到正常响应，再 fuzz 字段。若自定义头全部因编码错位报 500，旧测试应标“无效测试”并在修复后复查，不能标“应用不读取头”。签名字段先用已知合法值验证载体，随机 marker 可能在验签前被丢弃。[协议与解析边界](protocols.md) 包含 AJP/HTTP 的校准点。

**数学与搜索**：统计拟合、LLL、BFS 或爆破前写清未知量、约束数与数据来源；先检查有无无噪声行、稀疏 support、小秘密和可逆轮函数。换模型时保持原始方程的回代路径。有限次数 Fermat/rho 失败不能证明“因子不小”或“只剩 GNFS”；模型欠定时给出多解，不用自然语言可读性证明唯一性。判定型问题（逐样本 0/1）里，“判否”只是否定证据：记录 β、格维、AUTO_ABORT、已复核样本数和停止条件，抬参数复核后才能排除该路线。

## 恢复记录

先核对题目身份：题名、输入附件哈希、服务指纹与实例。相同工作目录的 OSINT 进度和 Agent 审计 WP 可能属于两道题；新 WP 只有在身份匹配时才能替代旧未解状态。同一题的多个工作目录也不能默认共享 nonce、worker 或连接状态。

在题目工作目录维护一份 `PROGRESS.md`，有实质变化就更新：

```text
更新时间 / 当前状态（候选、本地通过、远程成功、平台接受、未解）：
范围 / 附件路径与 SHA256 / 实例标识 / 协议与版本：
最近确认点：输入、命令、输出证据路径、证据等级
有效原语：能力、限制、同连接/同进程/同会话条件
尝试账本：假设 | 前提 | 输入 | 预期 | 实际 | 已排除/待定/测试无效
阻塞层：传输/解析/身份/状态/模型/依赖/部署/验证
正在运行：PID或会话、日志、已处理范围、检查点、内存/时间预算（没有则写无）
下一步：1–3 个测试，各自能排除什么、预算和停止条件
复现入口：脚本、解释器/依赖、参数；实例重开后需重取的状态
```

新结果优先于旧状态文件，保留冲突和修正依据。`PROGRESS.md` 的“未解”若已有较新 WP 和服务响应，应更新状态；脚本名 `final.py`、产物名 `FLAG.txt` 自身不是证据。无法验证的外部页面、验证码或账号问题交接具体缺口，避免不停换代理、撞字典或创建外部资源。

每次退出一条路线时写清：`排除的具体模型/输入域 → 支撑观测 → 会使结论失效的前提变化`。修复后客户端与旧客户端的结果分开，旧失败标作无效；有限词典、路径扫描与正常基线不支持“管理员不存在”“只有三个资源”“唯一剩余方向”等穷尽断言。身份、OAuth 与受限 pickle 的分层测试见 [Web 状态与对象边界](web-state.md)。
