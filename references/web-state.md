# Web 状态、对象与前置闸门

用于受限 pickle 黑盒、OAuth/PoW、多站点会话与业务计数。先建立合法端到端基线，再逐层测试；不要把前置校验的拒绝归因于后面的业务规则。

## 受限 pickle：先证明送达哪一层

画出 `表单/base64 → opcode/FRAME → find_class → 构造/BUILD → 顶层类型 → 必填字段 → fmt/模板 → 业务副作用`，每层保留一个合法对照。导出对象可用 `pickletools.dis`/`genops` 静态分析；不在宿主直接 loads 不可信对象。

- 白名单区分 module-only 与 `(module, name)` 精确匹配，且检查各实际构造路径。允许一个业务类既不等于可加载所有同模块对象，也不证明没有可用 gadget；追该类的构造、`__setstate__`、属性读取和格式化消费者。
- 对象字段变异时保留全部必填字段与合法值，仅改一项。前序字段缺失的 `AttributeError` 会遮蔽后续类型行为；“must contain”报错文案不证明容器可包裹顶层对象。
- `NEWOBJ` 通常不调用 `__init__`；构造实例后推入 state 字典，必须经正确 `BUILD` 才能应用，不能仅把字典留在栈上。逐条记录 opcode 的栈效果、memo 引用、MARK 和 STOP。
- 手写编码器先对**自己生成的无害基础类型**做本地往返及标准库输出对照，再拼业务对象。`SHORT_BINBYTES` (`C`) 长度为 **1 字节**，`BINBYTES` (`B`) 长度为 4 字节小端；`LONG1` (`0x8a`) 是 1 字节长度，`LONG4` (`0x8b`) 是 4 字节长度，payload 为有符号小端补码。`FROZENSET` (`0x91`) 消费 MARK 后的元素，空集合也不能省掉 MARK。协议没有通用“complex opcode”；`Y` 不能当复数编码，STOP (`.`) 不能当 Ellipsis 值。
- `pickletools.dis` 能查许多语法/栈错，但不能证明自定义类的运行语义。对受控 stub 类可用本地隔离消费者做对象形状对照，标明与目标类实现的差距。
- `UnpicklingError/TypeError/AttributeError` 是可用的分层信号，须结合合法对照定位；500 后是否有副作用另查。实例属性覆盖无效只排除该消费者读取实例属性的假设，不能证明模板来自类常量。

## OAuth / PoW / 会话

将题目暴露的 app、IdP、挑战服务、管理员站分别列出 origin、路由、cookie、CSRF、state、flow 和返回状态。仅在已确认题目范围内访问这些站点；外观与真实产品相似不扩展测试范围。

1. 从真实页面脚本/网络请求恢复 token 的生成端点、JSON 或 base64 表示、flow、nonce、有效期和绑定条件；旧版 prepare/finalize 的结果不能直接替代新版 challenge 协议。
2. PoW 先用下发 seed/difficulty 校准编码、比较运算与字宽，再估吞吐。JS 的 UTF-16、32-bit 乘法与 JSON 序列化须对拍；硬编码日期、UA 或随机字段即使偶尔通过也只是当前条件成立。
3. 每个登录阶段检查响应类型、错误码和业务字段，再取 callback。保持同一会话所需 cookie；签名有效、OAuth code 发放、callback 完成与身份提升分别验证，不能把自动重定向后的 200 当作登录成功。
4. 开放 redirect_uri 需要继续证明 code 与 state/client/PKCE 的绑定及可兑换性；验证码样例、站点 claim 或前端角色都不自动授予权限。

## 会话与闸门顺序

服务端把会话落到外部存储（Redis/文件/DB）时，先定四件事再写：`session.save_handler` 与键名前缀（按"常见前缀 + 自己 SID"实测候选，不套定值）、SID 字符集（不合 PHP 默认字符集的 SID 会被丢弃）、`use_strict_mode`（开启时未存在的 SID 不被读取，须先落一次真实 session 再覆盖同键）、`session.serialize_handler` 决定外层格式（`name|s:len:"..."`），应用内层加密不改变外层可追加变量。

- 能写入会话状态后，按"字段名 + 类型"逐个试短路点：形如 `defined $s->{sudo_until} && =~ /^\d+$/ && > time()` 的时间戳字段位于认证检查之前时会直接返回真。
- 凭据/session 的解析注入：若 cookie 形如 `id=<token>,<scramble>` 且只判第二段"存在"不判非空，空段可能使"加密"退化为明文；Basic 认证若只按冒号/换行切分，`pass` 内塞换行加额外 `k=v` 可凭空造状态字段。前提是能发含控制字符的原始请求。
- 写后读不到新值：走"同一逻辑对象、不同字符串 key"（zone 不匹配路径、`./` 与 `.//` 等价族）逼缓存重扫再读；先证明写入已落存储，否则只是没写进去。

## 计数与 bot 的观测

用 `操作前计数 → 一次已知成功操作 → 操作后计数 → 对照账户/未登录观测`，区分本账户 quota、key quota、全局计数、免费层上限与缓存。背景计数变化不能自动归因于某个 bot；计数停滞不独立证明数据库种子缺失。

bot 测试分开证明“访问、执行脚本、身份、可访问资源和寿命”。同源无害写回可帮助观测；持久 localStorage、跨域 WS 建连与管理员身份是不同事实。已有合法业务链受限时，先定位权限闸门及正常功能，不用批量注册、无界发消息或持续词典扫描替代模型；但已取得审批/额度聚合权限、且计数口径已定标时，批量注册本身可以是正解，不因“批量”二字排除。JWT/session 与部署诊断见 [阻塞诊断](blockers.md)。
