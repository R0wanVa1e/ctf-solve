# 简版 WP 模板

解出并核验 flag 后，在题目工作目录生成 `writeup.md`。目标是让别人按步骤复现，不写成长篇教程。

```markdown
# <比赛 / 题目名> - <方向>

## 结果
- 状态: <算法候选 / 本地校验通过 / 远程成功 / 平台接受>
- Flag: `<已核验的 flag；未达到远程或平台确认时写“候选”>`
- 核验依据: <文件路径、服务端响应、校验器或平台响应>
- 仍有冲突: <平台拒绝、多解、动态实例或版本差异；无则写“无”>

## 环境
- OS / 架构 / 关键版本:
- 附件与服务协议:
- 依赖:

## 解题步骤
1. <观察到的关键事实与证据>
2. <漏洞/数学结构/数据处理方式>
3. <如何到达 flag，并如何验证>

## 复现
- 命令: `<准确命令>`
- 输入/参数: <文件、环境变量、靶场地址占位符>
- 预期结果: <flag 或判定成功的输出>
- 复跑结果: <已复跑 / 未复跑及原因>
- 证据等级: <E0–E4，定义见 ctf-solve 技能 references/evidence.md>

## 脚本（如有）
- 文件: `<相对路径>`
- 用途与关键逻辑: <说明输入如何变成利用链/flag>
- 依赖及版本: <安装命令或标准库说明>
- 参数/环境变量: <名称、含义、示例值占位>
- 运行命令与预期输出: <可复制命令及结果>
```

脚本必须与 WP 一起保存在工作目录，入口参数、依赖和成功判据写清楚；避免硬编码临时靶场地址、token 或个人路径。只用命令而无需脚本时，把完整命令和必要输入写入“复现”。报告内容以实际证据为准；未复跑就明确标注，不声称已验证。

完整入口还包括本地 import 的辅助模块、字典/表与附件相对路径；`exp2.py` 依赖 `exp.py` 时两者都列出，并检查 import 会不会自动连接旧实例。用显式参数选择远程目标，设置超时/有限重试，成功后非破坏性退出；保存原始返回值，大小写和字节不自行归一化。flag regex 仅提取候选，不代替业务成功条件或认证校验。

每个决定性步骤附实际命令及最小请求/响应、hexdump 或程序输出，引用落盘证据；HTTP 样包保留方法、request-target、必要头和 body，删去无关长输出。命令块不在续行反斜杠后放行内注释。核验脚本发现残差超界、认证失败或原程序拒绝时必须非零退出，不能仅打印警告后继续写 `verified_flag.txt`。未完成题更新 `PROGRESS.md`（见 [阻塞诊断](blockers.md)），不要用成功 WP 模板掩盖卡点。
